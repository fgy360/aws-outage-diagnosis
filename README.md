## 先分清：是亚马逊挂了，还是你自己的连接出了问题

判断标准就一条：看“挂”的范围有多大。三步走：

1. 打开 AWS 官方的 Service Health 状态页，或登录控制台查看 Health Dashboard。上面如果标红了 us-east-1（美东·弗吉尼亚）之类的区域，说明是亚马逊那边的事故，你这边做什么都没用。
2. 状态页干净的话，去 Downdetector 这类第三方监测站搜一下，看是否有大量用户在同一时段报告故障。
3. 两边都正常，只有你在掉线报错，问题就出在本地到亚马逊之间的链路上，按下面的报错类型挨个处理。

有个细节能帮你快速缩小范围：同一网络下其他联网应用都正常、唯独 WorkSpaces 报网络错误时，先确认设备满足至少 1 Mbps 的下载带宽——这是 WorkSpaces 客户端的硬性底线，设备间歇性连网时客户端也会报网络问题。

## 2025 年 10 月那次大瘫痪：大型 AWS 故障长什么样

那次故障的源头是亚马逊 AWS 位于北弗吉尼亚的数据中心。AWS 在状态页确认，美国东部区域多项服务错误率升高、延迟增加，其中 DynamoDB 的请求错误率显著上升。DynamoDB 是支撑数千家企业程序运行的数据库服务，这也解释了为什么一家云厂商出事能把这么多网站拖下水。

受影响名单很长：亚马逊自家的电商门户、Alexa、Prime Video；金融类的 Robinhood、Coinbase、PayPal 旗下 Venmo、Chime；流媒体的 Disney+、Apple TV；社交与游戏侧的 Snapchat、Reddit、Roblox、堡垒之夜、Steam、PlayStation Network、Xbox；连麦当劳、《华尔街日报》、Perplexity、多邻国都在列。英国同样中招，劳埃德银行、哈利法克斯银行和苏格兰银行的网银打不开，英国税务系统的在线服务也受影响。Perplexity 的 CEO 斯里尼瓦斯当时在 X 上发帖，直接把原因归结为“宕机的根本原因是 AWS 出现问题”。

这种量级的事故，用户端没有任何修复手段。AWS 当时的通报是“正通过多路径并行方案全力加速恢复服务”。你能做的是两件事：等官方恢复；事后梳理业务对单一区域、单一服务的依赖，把鸡蛋从同一个篮子里挪出来。第二条正是本文后半部分要展开的。

## WorkSpaces 连不上：按报错类型对症修

WorkSpaces 的连接故障基本集中在五种情况：报“无网络”、卡在登录页、证书错误、速度慢警告、安全软件拦端口。对照报错信息处理就行。

### 报“无网络。网络连接中断。请检查网络连接”

先看是不是用了自定义代理。3.0 以上版本的 Windows、macOS、Linux 客户端配合自定义代理时都可能触发，处理方式各不相同：

- **Windows 客户端**：升级到 3.0.12 或更高版本
- **Linux 客户端**：升级到 3.1.5 或更高版本；实在升不了，改用操作系统里配置的代理
- **macOS 客户端**：改用系统级代理，不用客户端里的自定义代理

没在用代理的话，留意另一个相关报错：“设备无法连接到注册服务。请检查网络设置。"——同样从网络设置和代理配置入手。

### 卡在“准备登录页面”

Windows 10 上的 3.0.4 和 3.0.5 版客户端会卡在这个界面出不来。两条路：升级到 3.0.6 及以上版本，或者不用管理员（提升）权限运行客户端。

以管理员权限运行还有个副作用——高 DPI 屏幕上登录页面会小得没法看。正常在用户模式下运行即可，顺带把“登录页面非常小”的问题一起解决。

### 登录后白页，或者提示“无效证书”

两种都是证书问题，但修法完全不同。

登录后 Windows 客户端只显示白页，多半是本地电脑上过期的 Verisign/Symantec 证书在捣乱。打开控制面板，进入“网络和 Internet → Internet 选项 → 内容 → 证书”，在“中间证书颁发机构”和“受信任的根证书颁发机构”两个选项卡里，把 Verisign 或 Symantec 颁发且已过期的证书删掉——没过期的千万别动——然后重启客户端。

客户端直接弹“无效证书”错误，最常见的根因是代理服务器剥掉了根证书颁发机构，返回给客户端一个不完整的证书。这个问题在客户端侧无解，联系网络管理员。

还有一类更隐蔽：WorkSpaces 从 2018 年 5 月起强制使用亚马逊信任服务（Amazon Trust Services）签发的数字证书，操作系统根证书列表太旧的设备会直接连不上。PCoIP 零客户端会明确提示“服务器提供的证书无效”（时间戳不对，或本地证书库里找不到根），其他客户端的健康检查会在“互联网”一项显示红色三角。Windows 用户从 WorkSpaces 官网的客户端下载页安装最新版，安装过程会自动补齐系统对亚马逊信任服务的信任；其他平台联系管理员处理。

### 提示“网络连接速度很慢”

这是延迟警告：你到 WorkSpace 的往返时间超过了 100 毫秒。能用，但体验会打折。官方给出的两个最常见原因和对应基准：

- 离 WorkSpace 所在的 AWS 区域太远，最好保持在 2,000 英里（约 3,200 公里）以内
- 网络本身慢或不稳：至少 300 kbps 才能基本使用，看视频或跑图形密集型应用需要 1 Mbps 以上

这两组数字后面还会用到——它们也是“要不要备一条线路”的判断依据。

### 装了第三方安全软件后彻底连不上

WorkSpace 需要开放特定的入站和出站端口，安全软件或防火墙把这些端口挡住，WorkSpace 就会失联。还能登录的话，先核对官方文档里的端口要求再放行；已经彻底进不去，只能让管理员重建 WorkSpace，然后重装软件、重新配好端口。

## 管理员侧：看日志，别靠猜

负责维护的人遇到用户反馈连不上，直接开高级日志比来回猜省事。关掉客户端后带 `-l3` 参数启动：Windows 在安装目录运行 `workspaces.exe -l3`，macOS 执行 `open -a workspaces --args -l3`，Linux 执行 `/opt/workspacesclient/workspacesclient -l3`。日志分别落在 `%LOCALAPPDATA%\Amazon Web Services\Amazon WorkSpaces\logs`（Windows）、`~/Library/Application Support/Amazon Web Services/Amazon WorkSpaces/logs`（macOS）和 `~/.local/share/Amazon Web Services/Amazon WorkSpaces/logs`（Linux），2.0 以上客户端还会自动上传到 AWS。拿着这些日志去找 AWS 支持，比截图描述高效得多。

实例刚启动或重启后报“WorkSpace 状态：不健康。我们无法将您连接到您的 WorkSpace”，先等几分钟再试，启动过程中这个提示是正常的；持续报错再重启或重建。另外几件容易忽略的事：组策略导致的登录延迟（登录要几分钟）属于正常现象，不用重装客户端；WorkSpace 默认不能访问互联网，需要管理员显式开通；Web Access 登录黑屏或超长，一般是 Windows 组策略和安全策略配置不当，同样归管理员管。

## 常见问题

### WorkSpaces 报网络错误，但浏览器能上网，怎么回事？

最常见的原因有三个：设备不满足 1 Mbps 下载带宽、网络间歇性断连、操作系统根证书列表过旧。前两个换网络环境就能验证，第三个装最新版 Windows 客户端即可自动补齐对亚马逊信任服务的信任。

### AWS 宕机时我能做什么？

等官方恢复，仅此而已。2025 年 10 月美东 DynamoDB 事故这类故障，用户端没有任何修复手段。事后值得做的是梳理业务依赖，准备备用入口。

### “无效证书”错误是什么意思？

客户端无法通过 SSL/TLS 验证 WorkSpaces 服务的身份，最常见的原因是代理服务器剥离了根证书颁发机构、返回了不完整的证书，需要网络管理员处理。

### 往返延迟多少算慢？

超过 100 毫秒客户端就会发“网络连接速度很慢”警告。官方基准：距离 AWS 区域 2,000 英里以内，带宽至少 300 kbps，视频和图形应用 1 Mbps 以上。
